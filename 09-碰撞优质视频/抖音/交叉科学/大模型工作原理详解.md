# 大模型工作原理详解

> 配合"交叉科学"的 DeepSeek V4 可视化视频食用。那个视频用游戏闯关的形式带观众体验了大模型推理全流程，但用比喻盖过了很多细节。以下是逐环节的人话拆解。

---

## 总览：一个词一个词地往外蹦

你输入"我饿了想吃饭"，模型输出"了"、再输出"吗"、再输出结束标记。

每一次只输出一个词，然后把这个词加到输入里，重新走一遍全流程。这就是"自回归"。

全流程可以浓缩为一张图：

```
你的输入
  ↓
分词 → 向量化 → 加位置
  ↓
┌──────────────────────────────────┐
│  Transformer 层 × 几十层          │
│  每层：                           │
│  注意力(QKV) → 残差 → 前馈 → 残差 │
│  [MLA 压缩 KV]   [MoE 多专家]     │
└──────────────────────────────────┘
  ↓
线性投影 → Softmax → 选出最优词
  ↓
输出一个词 → 加回输入 → 再走一轮
```

---

## 第一步：分词（Tokenization）

模型不认识汉字，只认识数字。所以先把句子切成小块，每个小块叫一个 **token**。

```
"我饿了想吃饭"
  ↓
["我", "饿了", "想", "吃饭"]
  ↓
[1024, 5837, 291, 8462]
```

切得越细，词表越大，模型能处理的语义越丰富。

> DeepSeek V4 的词表有十几万个 token。注意：一个中文词通常 = 1~2 个 token，英文一个词可能 = 2~3 个 token。这就是中文比英文便宜的原因之一——同样意思，token 数量少。

---

## 第二步：向量化（Embedding）

数字 ID 本身没有语义。"1024" 和 "5837" 之间没有关系。

Embedding 做的事：把每个 token ID 映射到一个 **高维向量**（比如 7168 维的数组）。这个向量就是这个词的"含义指纹"。

```
"我"   → [0.03, -0.15, 0.72, ...]  (7168 个小数)
"饿了" → [0.41, 0.08, -0.33, ...]
"想"   → [-0.12, 0.55, 0.19, ...]
"吃饭" → [0.27, -0.08, 0.61, ...]
```

**关键洞察**：含义相近的词，向量方向也相近。"饿了"和"想吃"的向量会比较接近，而"饿了"和"汽车"的向量差很远。这就是模型理解语义的基础。

---

## 第三步：位置编码（Positional Encoding）

模型同时看所有 token，不是按顺序读的。但"狗咬人"和"人咬狗"完全不一样。

所以在向量里注入位置信息：第1个位置加一组数，第2个位置加另一组数。这样相同的词在不同位置，向量就不同了。

---

## 第四步：注意力机制（Attention）—— 最核心的发明

一句话概括：**让每个词去问其他所有词"你跟我有什么关系"**。

三个矩阵：

| 矩阵 | 全称 | 作用 |
|------|------|------|
| **Q**（Query） | 提问 | "我"问全场——你们谁跟我有关？ |
| **K**（Key） | 索引 | 每个词贴标签——"我是'饿了'，是动词" |
| **V**（Value） | 内容 | 每个词的真实含义 |

流程：
1. "我"的 Q 去和 "饿了""想""吃饭" 的 K 做点积，算出相似度
2. 得到分数："我↔饿了" 0.8，"我↔吃饭" 0.6，"我↔想" 0.4
3. 用这些分数作为权重，把各个 V 加权求和

**结果**："我"被重新定义了。经过注意力之后，"我"不再只是一个孤立的词，而是吸收了整句话里其他词的含义——变成了"一个饿了想吃饭的我"。

> 这就是 AI "理解上下文"的本质。不是真的理解，而是通过向量运算重新编码了每个词在句子里的含义。

---

## 第五步：多层堆叠（Transformer Layers）

一层注意力不够。

- 第 1 层："我饿了"（理解基本主谓关系）
- 第 5 层："因为饿了所以想吃饭"（理解因果关系）
- 第 30 层："这种饿到底是生理饥饿还是心理空虚？"（深层语义）

每往下一层，理解就深一层。**几十上百层的堆叠，是模型从"看得懂字"到"读得懂意"的过程。**

---

## 第六步：残差连接 + 归一化

问题：几十层算下来，原始信息慢慢被稀释了。

解决：**旁路直通**。每层的输出 = 注意力加工结果 + 原始输入。

```
输出 = Attention(输入) + 输入
```

就算某一层算了错的东西，原始信息还在。这就是视频里说的"支路"和"超链接"——残差连接（Residual Connection）。

---

## 第七步：前馈网络（Feed-Forward Network）

注意力让词之间互相交流完了，还要过一个**独立加工厂**。

- 注意力 = 词和词之间交换信息
- 前馈 = 每个词自己深度加工

大多数参数都在前馈网络里。一个 70B 参数的模型，可能 60B 都堆在前馈网络上。

---

## 第八步：KV 缓存压缩（MLA）—— DeepSeek 的核心创新

注意力计算需要存储 K 和 V（每个 token 的两个矩阵）。输入10万个 token，KV 矩阵就大到爆显存。

DeepSeek V4 的做法叫 **MLA（Multi-head Latent Attention，多头潜在注意力）**：

- 不存完整 KV，而是把 KV **压缩成一个极小的潜在向量**
- 需要计算时再从这个潜在向量还原
- 同时保留最近几个 token 的**高清未压缩版本**（滑动窗口机制）

**效果：显存省 80% 以上，推理成本大幅下降，精度损失极低。**

> 视频里"每4个 KV 压成一个精华线" + "最顶部的4个方块保留" = MLA + 滑动窗口。

---

## 第九步：MoE（混合专家模型）

传统模型只有一个前馈网络。DeepSeek V4 有**很多个**——叫"专家"。

```
"饿了" → 门控网络 → 激活 专家#3（饮食语义）+ 专家#17（身体状态）
"想吃饭" → 门控网络 → 激活 专家#3（饮食语义）+ 专家#42（动作意图）
```

**总参数量巨大（671B），但每次推理只激活一小部分（比如 8 个专家，约 37B）。**

这就是 DeepSeek V4 又快又便宜的秘密：参数多所以知识丰富，激活少所以计算便宜。

---

## 第十步：线性投影 + Softmax（输出）

最后一层算完，得到了一个 7168 维的向量——人类看不懂。

- **线性投影**：把 7168 维向量映射到词表大小（十几万维），每个维度对应一个词的分数
- **Softmax**：把分数转成概率

```
"吃饭": 0.72   ← 最高，选这个
"睡觉": 0.15
"跑步": 0.03
...
```

选概率最高的那个词作为输出。

---

## 最后一步：自回归（Autoregression）

```
输入 "我饿了想吃饭" → 输出 "了"
输入 "我饿了想吃饭了" → 输出 "吗"
输入 "我饿了想吃饭了吗" → 输出 <结束>
```

每次只生成一个词，用这个词作为下一次的输入，循环到结束。这就是 AI 一个字一个字往外蹦的原因。

---

## 成本与你相关

| 环节 | 成本占比 | 为什么 |
|------|------|------|
| Token 输入 | 小头 | 嵌入计算很便宜 |
| 注意力计算（QKV） | 中头 | 每层都要算，平方级增长 |
| 前馈网络 | **大头** | 大多数参数都在这里 |
| MoE 专家选择 | **省钱** | DeepSeek 只激活 8 个而非全部 |
| KV 缓存 | **隐性大头** | 长对话时 KV 一直存在显存里，越聊越贵 |

这解释了柯哥问过的两个问题：
1. **为什么长对话越来越贵？** KV 缓存一直在涨，不释放
2. **为什么 DeepSeek 便宜？** MLA 压缩了 KV + MoE 只激活部分专家

---

## 延伸理解：训练 vs 推理

上面说的全部是**推理**（用模型生成文字）。模型是怎么学到这些的？是**训练**：

- **预训练**：喂几十万亿 token 的互联网文本，让模型学会"下一个词是什么"
- **微调**：用人类标注的高质量对话微调，让模型学会"怎么和人对话"
- **RLHF**（人类反馈强化学习）：人类给模型输出打分，模型学会"怎么说人话、符合人类偏好"

推理是"用脑子"，训练是"长脑子"。我们今天讨论的全是推理。

# 思考方式：MECE原则——分类无重叠无遗漏

> 把你已经在做但说不清楚的事，给它一个名字。
> 有了名字，下次教客户、带员工，就能说清楚为什么他的分类有问题。

## 核心就两句话

**不重叠，不遗漏。**

拆一个东西的时候，拆出来的部分：
- 哪个都不能同时属于两个分类（不重叠 / Mutually Exclusive）
- 所有部分拼回去刚好是完整的（不遗漏 / Collectively Exhaustive）

## 自检三个问题

每次分类完，强制问自己：

1. **有没有东西能同时被分进两个类别？**
   → 有 → 分类有重叠，重新划

2. **有没有东西哪个类别都放不进去？**
   → 有 → 分类不穷尽，补一个

3. **这组东西能用一个名词概括吗？**
   → 说得出（原因 / 步骤 / 坑 / 方法 / 标准）→ 分组有意义
   → 只能说"事情""方面""东西" → 太宽泛，这组是凑出来的，重新分
   → 有一个根本塞不进概括词 → 有异类混进来了，踢出去或重组

## 在我工作里怎么用

**做客户受众分类：**
- ✅ 年轻夫妻 / 有娃家庭 / 老人家庭 → MECE通过
- ❌ 年轻夫妻 / 高收入家庭 / 有房一族 → 全重叠，同一个人三个都占

**列内容方向：**
- ✅ 获客内容 / 转化内容 / 交付内容 → 三个桶互不重叠，合起来覆盖客户全生命周期
- ❌ 干货内容 / 涨粉内容 / 变现内容 → 干货可以用于涨粉，也可以用于变现，重叠

**做账号诊断报告：**
- 拆完问题之后用MECE检查：有没有两个问题其实是同一件事？有没有漏掉哪个维度？

**检查别人的汇报：**
- 把对方的理由一条条列出来，按MECE归类：有没有重复的？有没有漏的？
- 11条理由有可能就是5个核心因素翻来覆去地说

## 关键：归纳之后还要追问

很多人只做了归纳（找共同点，分类），但忘了检查是否穷尽。

分好了衣服：上衣、裤子、袜子，但地上还扔着一条围巾——分类本身没问题，缺的是"检查是否穷尽"这一步。

**完整流程：先归纳 → 再检查 → 确保无遗漏**

这是一种思考方式，不是工具。工具用完就放，思维方式会渗透进所有分类动作里。

## 不适用

追求穷举、顺序比分类更重要的场景（如SOP操作步骤）。

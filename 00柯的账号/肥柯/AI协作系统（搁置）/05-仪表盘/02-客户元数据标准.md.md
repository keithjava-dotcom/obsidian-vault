# 客户元数据标准

## 这份文件是什么

每个客户在自己的目录下有一份「客户元数据.md」。
这份文件的 frontmatter 字段就是仪表盘的"数据库列"。

只要你按这份标准给每个客户写元数据,仪表盘就能自动汇总。

## 标准模板

新客户接入时,在该客户的目录下创建一份 `客户元数据.md`,
内容如下:

```markdown
---
client_role: client                       # 必填,固定为 "client"
client_name: 菲菲                         # 必填,客户的称呼
client_real_path: 04服务客户/大连/心理咨询室/菲菲   # 必填,真实目录路径
client_id: feifei                         # 必填,英文小写无空格,用作唯一标识
client_status: active                     # active / paused / ended

# 服务阶段(对应"客户服务流程模板"的8个阶段)
service_status: 阶段4-稿件交付             # 当前阶段
service_substatus: 第07稿-起草中           # 阶段内的子状态(可选)

# 交付节点
last_delivery_date: 2026-05-04            # 最近一次交付日期
next_milestone: 第07稿-定版                # 下一个里程碑
next_milestone_due: 2026-05-10             # 下一个里程碑预计日期(可选)

# 柯哥审核待办池
柯哥审核待办:                              # 列表,可多项
  - 第07稿-标题候选
  - 5月复盘报告

# 风险等级
risk_level: 低                            # 低 / 中 / 高
risk_reasons: ""                          # 风险描述(中/高时必填)

# 客户特性(供 Hanako 快速调用)
ip_voice: 心理咨询师·温和理性             # IP 语气一句话描述
core_pain: 婚姻情感咨询的女性受众          # 客户核心痛点(简述)

# 元数据
client_since: 2026-04                     # 服务开始月份
total_deliveries: 5                       # 已交付总数(手动维护)
last_review_date: 2026-05-06              # 最近一次复盘日期

# Hanako 协作状态
hanako_engaged: true                      # Hanako 是否在为该客户工作
last_hanako_action: 2026-05-06             # Hanako 最近一次产出日期

# Claudian 协作状态
claudian_engaged: false                   # Claudian 是否参与
last_claudian_review: ""                  # Claudian 最近一次抽查日期
---

# {客户名} · 客户元数据

(下面写一些 frontmatter 不方便表达的内容,比如客户的特别约定、
柯哥与客户的私人关系备注等)
```

## 字段优先级

**必填(没有就在仪表盘上消失)**:
- `client_role: client`
- `client_name`
- `client_real_path`

**强烈建议**:
- `service_status`
- `last_delivery_date`
- `risk_level`

**可选**:其他字段都可以慢慢加。

## 字段更新责任

| 字段 | 谁来更新 |
|------|---------|
| client_role / client_name / client_id / client_real_path | 柯哥(创建时) |
| service_status / next_milestone | 柯哥(每次状态推进) |
| 柯哥审核待办 | 柯哥 / Hanako 起草后追加 |
| risk_level | 柯哥(根据情况) |
| ip_voice / core_pain | 柯哥(从客户档案提炼) |
| last_delivery_date | 柯哥(交付时更新) |
| total_deliveries | 柯哥(手动维护) |
| hanako_engaged / last_hanako_action | Hanako(她自己产出后追加) |
| claudian_engaged / last_claudian_review | 柯哥(召唤 Claudian 后) |

## MVP 启动:菲菲的元数据

第一个该建的元数据文件是菲菲的。

**路径**:`04服务客户/大连/心理咨询室/菲菲/客户元数据.md`

**内容(基于你今晚告诉我的信息)**:

```markdown
---
client_role: client
client_name: 菲菲
client_real_path: 04服务客户/大连/心理咨询室/菲菲
client_id: feifei
client_status: active

service_status: 阶段4-稿件交付
service_substatus: 第07稿-待启动

last_delivery_date: 2026-05-06
next_milestone: 第07稿-定版

柯哥审核待办: []

risk_level: 低
risk_reasons: ""

ip_voice: 心理咨询师·待柯哥确认细节
core_pain: 婚姻情感受众·女性·从已发稿子提炼

client_since: 2026-04
total_deliveries: 5
last_review_date: 2026-05-06

hanako_engaged: true
last_hanako_action: 2026-05-06

claudian_engaged: false
last_claudian_review: ""
---

# 菲菲 · 客户元数据

服务阶段:稳定期,持续出稿。
今天柯哥已认可 Hanako 的 06-复盘记录-2026.5.6 和 07-选题诊断-2026.5.6 两份产出。
下一步:Hanako 按 MVP 新规则接入,准备起草第 07 稿。
```

⚠️ **不要立刻建这个文件**。
等你完成 Hanako 的 MVP 接入后,再建。
原因:`ip_voice` 和 `core_pain` 这两个字段需要从「04-语言风格指南.md」精确提炼,
不要仓促填,免得错了反而误导 Hanako。

## 渐进改造现有客户

不需要一次给所有客户加元数据。
建议节奏:
- **菲菲**:MVP 试点完成后(Hanako 接入完毕),柯哥手动建一份
- **其他在跑客户(偏偏、若溪、大成律所等)**:每次想到时顺手建,不强求
- **历史归档客户**:不需要建

## 仪表盘的演进

这份标准是 v0.1。
跑一段时间后会发现:
- 有些字段多余(没人用)
- 有些字段缺失(经常想看但 frontmatter 里没有)

每月底柯哥可以做一次"字段盘点":删多余的、加缺失的。
版本号递增,记录在《系统复盘记录.md》。

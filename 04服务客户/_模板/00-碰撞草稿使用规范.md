# 碰撞草稿区使用规范

## 目录结构

每个客户的碰撞草稿区位于：
```
04服务客户/[城市]/[客户名]-[领域]/00-碰撞草稿/
├── 文案碰撞/     ← 文案讨论、改稿过程、多版本对比
├── 选题碰撞/     ← 选题讨论、选题筛选、选题方向脑暴
└── 思路碰撞/     ← 定位思路、内容方向、策略讨论
```

## 默认规则

所有碰撞类内容（讨论文案、选题、思路），
默认写入对应客户的 `00-碰撞草稿/` 子文件夹。

碰撞草稿的文件命名：
`YYYY-MM-DD-[简短描述].md`

示例：
- `2026-05-11-两块钱选题讨论.md` → 选题碰撞/
- `2026-05-11-赵姐第01稿v1-vs-v2.md` → 文案碰撞/
- `2026-05-11-赵姐要不要做视频号.md` → 思路碰撞/

## 碰撞内容格式

碰撞文件不是正式交付物，格式从简：

```
---
author: [AI名称]
---

# [简短描述]

## 柯哥原话
（柯哥说的关键判断、反馈、方向）

## AI分析
（AI的推理过程、方案对比、利弊分析）

## 结论
（最终决定是什么，谁定的）
```

## 定稿流程

柯哥说"定稿"或"这个版本可以"
→ AI自动判断属于哪类内容
→ 转写到对应正式文件：

| 碰撞类型 | 定稿写入位置 |
|---------|------------|
| 文案碰撞 | `08-文案/第XX稿-[标题].md` |
| 选题碰撞 | `05-内容规划.md`（更新选题规划） |
| 思路碰撞 | `03-定位方案.md` 或 `05-内容规划.md` |

→ 草稿原文保留在碰撞草稿区，不删除。

## 清理规则

每月1号自动归档上月草稿。

归档目标：`00-碰撞草稿/归档/[YYYY-MM]/`

归档条件：
- 文件最后修改时间在上个月内
- 已有对应定稿转写的，可以归档
- 未定稿的碰撞内容，保留在原位置，不归档

归档后原目录只保留当月碰撞内容。

## 为什么要碰撞草稿区

之前的问题是：柯哥和AI讨论的过程中，
想法迭代快、版本多，
直接写正式文件容易把过程覆盖掉。

碰撞草稿区把"过程"和"结果"分开：
- 00-碰撞草稿/：过程，随便写，不怕乱
- 01~09：结果，每次更新都是定版

这样正式文件永远干净，
讨论历史也保留着能回溯。

# Data Source Routing — 数据源路由协议

被 cheat-seed、cheat-trends 引用。规定何时调热点工具、调哪个、不调时怎么办。

## 核心哲学

**热点工具是"前置素材库"，不是"主菜单"。**

- 用户在内省（讲自己经历/思考动机）→ 不调，避免外部信息污染
- 用户在找素材（没想法/要批量/显式抓热点）→ 调
- 用户在确认角度（讲了时事话题）→ 让用户决定

## Mode × 调用的默认策略

| cheat-seed Mode | 默认调？ | 触发条件 |
|----------------|---------|---------|
| Mode A（用户给具体经历） | ❌ 默认不调 | 仅当话题是时事+用户主动同意 |
| Mode B（方向不具体，问"为什么"） | ❌ 永远不调 | 用户在内省，外部素材是噪音 |
| Mode C（完全没想法） | ✅ 默认调 | Mode C 的核心动作 |
| --batch N | ✅ 默认调 | 批量 brainstorm 需要 anchor |
| /cheat-trends 显式 | ✅ 调 | 主入口，无需解释 |
| /cheat-recommend | ❌ 默认不调 | 已有 pool；>7天未更新才提示 |

## 时事判定（Claude 判断）

| 信号 | 含义 |
|------|------|
| 含专有名词（人名/产品名/事件名） | 强信号——可能是时事 |
| 含时间词（"今天"/"刚"/"最近"） | 强信号 |
| 含结构词（"对比"/"回应"/"事件"） | 弱信号 |
| 仅通用名词+个人经历词（"我"/"昨天"） | 反信号——长青个人经历 |

判定结果：
- 强信号 → 问用户"要不要拉舆论风向参考"
- 弱信号 → 直接深挖
- 反信号 → 100% 不调

## Content Form × Adapter 路由表

| content_form | 主调 | 备调 |
|-------------|------|------|
| opinion-video | trendradar-mcp | aihot（仅 AI 相关话题时） |
| long-essay | trendradar-mcp | aihot |
| short-text | trendradar-mcp | aihot |
| podcast | trendradar-mcp | aihot |
| tutorial-builder | aihot | trendradar-mcp |
| mixed | 两个都调 | Claude 判断归属 |
| other | trendradar-mcp | manual-paste |

manual-paste 永远是 fallback——用户粘 URL/标题列表。

## 优雅降级

所有失败都不抛异常。cheat-seed 永远能跑——区别只是有没有外部素材。

```
主调成功 → 拿数据 → 进流程
主调失败 → 备调 → 备调成功则拿数据+提示主调用不了
备调也失败 → manual-paste 兜底：问用户"今天看到啥可以拍的？"
无任何源启用 → 提示用户配置 + 直接走 manual-paste
```

## 成本控制

| 场景 | 调用频率 |
|------|---------|
| Mode C 触发 | 每次会话最多 1 次 |
| Mode A 灰色场景 | 用户同意才调，1 次 |
| --batch | 1 次拿足够 |
| 用户连说"再来" | 第 2 次允许，第 3 次提示"换角度" |

## 输出契约

热点工具抓的数据 → 去重（三重保护）→ 粗打分 → 写入 candidates.md（带 source 字段标明来源）

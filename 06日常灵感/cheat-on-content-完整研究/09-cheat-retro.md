# cheat-retro — ⭐复盘（对账）

## 定位

校准循环的反馈环节——T+N 天数据回收 + 对比预测 + 验证/推翻 + 提炼新观察。**不复盘的预测等于占星**。这是整个项目中质量最高的 skill。

## 工作流

```
[用户：复盘 predictions/<id>.md]
→ Phase 0: 校验 immutability + 校验时间窗口
→ Phase 1: 抓数据（manual 粘 or adapter 自动）
→ Phase 2: 写实绩段 + top 评论关键词聚类
→ Phase 3: 验证/推翻预测的各假设
→ Phase 4: 提炼新观察（写入 rubric-memo.md）
→ Phase 4b: diff scripts/ vs videos/script.md → 学改稿 pattern
→ Phase 5: 落盘（追加到 ## 复盘 段）
→ Phase 6: 写入 rubric-memo.md
→ Phase 7: 检测是否触发 bump 候选
```

## 核心设计：强制评论抓取

**强制要求 top 20+ 评论**（每条带赞数）。

> "评论才是真信号——'她不一样'这种模因爆发只能从评论看出。没评论的复盘 = 看体温计判断病情。"

用户拒绝 / 给少于 5 条 → 拒绝继续。

## 核心设计：Top 评论关键词聚类

把 N 条评论分成 3-5 类：
- 高赞模因（用户套用你的句式自嘲）
- 概念引用（引用你的观点展开讨论）
- 离题噪声（"第一" / "沙发" 等无意义）
- @朋友传播（"xxx 进来学"）
- 转发暴露暗示

## 核心设计：逐项验证/推翻

对 prediction 文件里的每一项（推理因素表、关键校准假设、反事实场景），逐项判定：

```
验证 ✅:
- 关键校准假设完全成立：本篇 71.1w / 谁问你了 11.7w = 6.07x
- ER=5 主导情感传播力 → H1 强证据

推翻 ❌:
- 中枢 50w 被超出 +42%
- SR 押注（"H2 SR 应上调"）反向被推翻
```

**纪律**：每条验证/推翻必须引用具体数据（分播比 2.53%），禁止"基本符合"含糊措辞。

## 核心设计：用户改稿 pattern 学习（Phase 4b）

diff scripts/<id>.md（pre-shoot 草稿）vs videos/<id>/script.md（实际拍摄稿）→ 找出改动及其流量影响：

| 用户做了什么 | 流量影响 | 是否追加 pattern |
|-------------|---------|----------------|
| 砍掉某段 | 实绩≥中枢→砍掉没伤流量 | 是，验证"那段冗余" |
| 加了互动钩子 | 实绩超中枢→可能是新 pattern | 是，候选 Pattern N |
| 改了风格 | 高于同类样本→有效 | 是 |
| 没动结构 | — | 不追加 |

## 写入 rubric-memo.md 的观察格式

```
### YYYY-MM-DD [标题简称] (id) — 一句话定性
- 预测：composite=X.XX，bucket=Y
- 实绩：播放 / 点赞 / 评论 / 转发
- Top 评论关键词：[简短摘录+赞数]
- 判断：哪个维度被验证/推翻？
- Rubric 调整：[如果有]
- 详见：predictions/<file>.md
```

**关键**：观察写入 rubric-memo.md（含实绩），绝不写入 rubric_notes.md（blind 白名单）。

## 关键设计洞见

1. **没有评论就不复盘**——"评论才是真信号，播放数永远告诉不了你什么内容真的击中了观众"
2. **每条验证/推翻引用具体数据**——"分播比 2.53%" 而不是 "互动不错"
3. **跨样本 pattern 检测**——扫描 rubric-memo.md 已有观察，≥2 样本支持→升级"重大跨样本观察"
4. **diff 脚本**——用户改稿的数据就是写作 pattern 的活样本
5. **immutability 校验**——写完后检查所有 ## 预测 段 hash 未变，变了回滚

# 融合到我们体系的方案

## 总体原则

**不要复刻全部 15 个子 skill**。只拿最有价值的设计融进现有体系。

改动面最小化——只改 fupan-workflow（核心改造）和 fanwen-workflow（加一步），不动 xuanti/dingwei/dagang 的主流程。

## P0 — 立即吃（改造 fupan-workflow）

### 我们在前预测层（发前）

在 fanwen-workflow 的交付前自检（0.4b）之后加：

**fanwen 交付前第 4 检：盲预测**

1. 调卡器（tiaoka）调该账号历史最佳/最差数据
2. 对新稿打 7 维分（ER/SR/HP/QL/NA/AB/SAT）→ 算 composite
3. 给 bucket + 概率分布（必须 100%）
4. 写反事实场景 + 关键校准假设
5. 预测段写入文件标 IMMUTABLE——发完后不管怎么复盘都不能改

**产出**：每条发前稿有一个预测文件，和原稿锁在一起。

### 我们在后对账层（发后）

fupan-workflow 改为**双环复盘**：

```
旧：数据来了 → 分析为什么好/差 → 结束
新：数据来了 → 对账：预测vs实绩 → 逐项验证/推翻 → 新观察 → 检测跨样本pattern
```

**具体改动**：
1. 强制抓 top 20+ 评论（带赞数），做关键词聚类
2. 对照预测文件，逐条判断：哪条推理因素被验证？哪条被推翻？
3. 提炼新观察，格式必须"可追溯到具体数据点"
4. 检测跨样本 pattern（≥2 样本支持→升级观察）

**产出**：每条复盘输出"验证/推翻"清单 + 新观察写入 rubric-memo.md

## P1 — 吸收设计（改造现有技能）

### Channel B 隔离打分

用 OpenClaw 的 sessions_spawn 实现：
- fanwen 写完 → spawn sub-agent <- 只收 [脚本, rubric]
- sub-agent 输出纯 JSON 打分 → 回传
- 主 Claude 自估一份 → 对比 → disagreement ≥2 → 弹柯哥裁定

### 评分标准升级 + 回测验证

fupan-workflow 累积观察 → 触发升级提议 → 新标准必须比旧标准在历史样本上更准 → 通过后才落地。

### 受众画像聚类

定位报告的"用户画像"模块补充"从评论反推受众"的数据层。不是替代柯哥的判断，而是给它一个数据锚点。

## P2 — 增强层（改 xuanti 等）

### 选题增强
xuanti-workflow 吸收：
- 对话式深挖（用户有主题时一次一个深挖，不是 15 候选砸脸上）
- 粗 rubric 筛选题（给 composite 作为排序维度之一）
- Buffer 颜色驱动推荐（断更风险高时限制推荐数量）

### 对标账号拆 pattern
sucai-mining 增强：
- 导入对标 5-10 条 → 拆写作 pattern → 写 script_patterns.md
- 用户标记"印象"（高/中/低+为什么）——暴露"用户想成为的 vs 数据"的 gap

## P3 — 轻量抄

- **Buffer 警戒系统**：给 goal-manager 加 buffer 颜色（发布 cadence × buffer 数）
- **Pending retros 自动排队**：发布后自动入队，过窗口期高优先级提醒
- **Shoot diff 检测**：b-roll-plan 记录拍后改稿 → 学柯哥/客户的改写 pattern

## P4 — 底层架构

- **Schema 迁移框架**：MEMORY.md/SOUL.md/AGENTS.md 的升级路径
- **脚手架初始化**：dingwei-report 的起步流程可以更轻量

|------|---------|-----------|

| Channel B 隔离 | 新建 scorer-blind sub-skill | 2-3 天 |

| 受众画像聚类 | dingwei SKILL.md 补充 | 1-2 天 |
| 其它增强 | 各 skill 小幅改动 | 3-5 天 |

## 先从哪开始推荐

**从 P0 的盲预测层开始**——只做柯哥自己主力账号。跑 3 条：
1. fanwen 写完稿 → 打 7 维分 → 写预测 → 发
2. T+3d → 对账 → 验证/推翻 → 写观察
3. 第三条一起看预测精度趋势

跑完 3 条就知道这套机制对柯哥账号的拟合度——**账号越垂直数据越稳，第一轮就有效**。

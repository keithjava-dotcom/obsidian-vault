# Observation Lifecycle — 观察生命周期

这是项目原则 #3（rubric 是工作台不是博物馆）的完整规范。

## 观察的生命周期

```
[新增] → [观察记录] → [跨视频观察] → [规律沉淀] / [被吸收为维度] / [被推翻]
  ↘
  [待验证假设]（暂存）
```

| 阶段 | 在 rubric_notes.md 的位置 | 触发 |
|------|--------------------------|------|
| 观察记录 | ## 观察记录 段 | 单次复盘后 |
| 跨视频观察 | ## 重大跨视频观察 段 | 同 pattern ≥2 样本 |
| 规律沉淀 | ## 规律沉淀区 段 | ≥2 样本+通过验证 |
| 待验证假设 | ## 待验证假设 段 | 单样本暂存 |

## 升格门槛

| 从→到 | 默认 | 可软违反（强信号时） |
|-------|------|-------------------|
| 观察记录→跨视频观察 | ≥2 样本 | 1 样本+评论区≥2000 赞模因 |
| 跨视频→规律沉淀 | ≥2 样本+不需改公式 | 1 强反例（≥3x 偏差） |
| 跨视频→维度 | ≥3 样本+通过 bump | 同 cheat-bump heuristics |

核心：**样本数是信号强度的代理，不是信号本身**。3 个清晰数据点 > 10 个零碎观察。

## 按校准池规模允许的动作

| 样本数 | 允许的动作 |
|--------|-----------|
| 1 | 单次观察记录，不能触发任何规则改动 |
| 2-4 | 提炼候选规律 + 跨视频观察，不动公式 |
| 5-9 | 修正维度定义（定性），不动权重数值 |
| 10-19 | 微调权重 ±0.2 |
| 20+ | 用回归反推权重（数据驱动） |

**关键**：不要 N=5 时就回归（过拟合），不要 N=20 时还用直觉调权重（有数据了）。

## 必须删除的条目

1. **被吸收为维度**：某个观察变成了正式维度 → 删掉观察记录
2. **被推翻**：新数据证明原来想的错了 → 删掉
3. **理由**：保留让读者困惑"这是历史还是仍生效的规则？"

## 不删除的条目

- 未解决的观察 → 迁移到"待验证假设"段
- 已沉淀的规律 → 保留在"规律沉淀区"
- 版本日志的升级 Memo → 保留在 rubric-memo.md

## 禁止的"博物馆冲动"

| 反模式 | 为什么不行 |
|--------|-----------|
| ~~旧值~~ → 新值（带删除线） | 用 git history 看旧值 |
| "我曾经以为…但其实…" | 让读者不知道当下规则 |
| "v1 时代 NA 是关键，v2 后发现不是" | 删 NA 相关条目，留版本 memo 解释 |
| "保留作为反例" | 反例在版本 memo 的"被推翻假设"小节 |
| "下次 bump 再删" | bump 落地时一起删干净 |

**git history 才是档案。rubric_notes.md 是当前生效规则的快照。**

## Blind Leak Guard（关键安全约束）

rubric_notes.md 是 cheat-score-blind sub-agent 的白名单——内容不能含实绩数据。

**禁止写入 rubric_notes.md 的模式**：

| 模式 | 替代位置 |
|------|---------|
| 真实视频标题+实绩 | rubric-memo.md |
| 派生证据带命名锚 | rubric-memo.md |
| 含 \d+w / \d+万 的数字（除 bucket 边界） | rubric-memo.md |

**允许的**：公式系数、维度定义（通用语言）、派生证据抽象化（不带样本名）、bucket 边界数字（属于规则不属于实绩）、观察 ID+一句话

**强制自检**：cheat-bump Phase 5 末尾 grep 排查 rubic_notes.md 是否含实绩 pattern → abort+回滚

## 健康体积参考

| 校准池 | 健康行数 | 警戒线 |
|--------|---------|--------|
| 0-5 | 100-200 | >300 |
| 5-20 | 200-400 | >500 |
| 20-50 | 300-500 | >700 |
| 50+ | 400-600 | >800 |

读者打开 rubric_notes.md 应在 60 秒内读完核心规则。

# Migration Protocol — 迁移协议

被 cheat-migrate skill、cheat-init、SessionStart hook 和维护者引用。

## 核心规则

### 版本哲学
- **MINOR**：加字段/软化 enum。不跑 migrate 也能工作（state.get 兜底），跑了让 state 完整
- **MAJOR**：删字段/重命名/改语义。必须跑 migrate，否则 skill 报错
- 模糊地带判定为 MAJOR——多写一份 migration 文件比让 state 出错好

### 约束
- 不跳版：多版升级按顺序应用每个 step，每步幂等
- 失败停在原地：不回滚，用户可在断点修复后从同位置继续
- 不降级：schema 演进单向。需降级 → cp 历史 git 快照
- 备份硬约束：写前必有 .backup-<timestamp>

## Schema 版本控制

```
migrations/
├── registry.md          # LATEST_SCHEMA + 版本链
├── 1.0-to-1.1.md        # 迁移文件
├── 1.1-to-1.2.md
├── 1.2-to-1.3.md
└── 1.3-to-1.4.md
```

## 迁移文件 4 段

每个 <from>-to-<to>.md 必含：

1. **WHAT changed** — 字段增删改
2. **WHY** — 为什么这么改
3. **HOW (Claude steps)** — 自然语言步骤（迁移是 Claude 读 markdown 跑的，不是自动脚本）
4. **Manual fallback** — 自动化失败时的兜底操作

写不出 4 段 = 改动太复杂没想清楚 = 不该 release 这次 bump。

## 读 state 的铁律

```python
# ✅ 好——MINOR 兼容
target_cadence = state.get("target_publish_cadence_days", None)

# ❌ 坏——老 state 缺字段 KeyError
target_cadence = state["target_publish_cadence_days"]
```

## SessionStart 检测

每次会话开始，hook 检测 schemaversion vs LATEST_SCHEMA：
- 不一致 → ⚠️ 建议跑 /cheat-migrate（不阻塞继续工作）
- MINOR 时大部分功能正常；MAJOR 时部分 skill 报错

## 维护者 checklist

发布前如果改 schema：
1. state.json 写入段 bump schema_version
2. registry.md 更新 LATEST_SCHEMA + 版本链
3. 写迁移文件（4 段）
4. CHANGELOG 标注 BREAKING/MINOR

## 备份清理

- /cheat-status 检测到有备份 + state 稳定 N 天 → 提示清理
- /cheat-init 重 init 时清理所有旧备份
- 不入版本控制（.gitignore 含通配规则）

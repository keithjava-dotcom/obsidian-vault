# AI工作流框架产品化：客户的第二大脑基建

## 原始想法

柯哥发现：现在很多客户需要他帮忙搭配AI工具工作流。他目前搭建的这套系统（小龙+Obsidian+AI框架）虽然主要服务新媒体短视频运营，但**底层框架是可以被借鉴的**。

客户的行业不同，但框架基建是通用的——把"新媒体运营"技能换成客户自己的专业内容，就是一套非常好的AI工作流系统。

**关键商业诉求**：搭建给客户用的时候，要让客户在使用过程中"忘不了柯哥"，因为后续有升单和其他商业活动。

## 核心洞察

1. **框架≠内容**：底层基建（Obsidian知识库+AI Agent+Skill系统+cron自动化）是通用的，上层替换专业模块即可
2. **"忘不了"=留存钩子**：系统本身就是一个天然的商业钩子——客户每天在用，每天在提醒"这是柯建军帮我搭的"
3. **升单路径**：基础框架部署 → 后续优化/扩展/培训 → 更高客单价的服务

## 可复用的底层框架组件

- Obsidian知识库结构（文件夹宪法+双向链接+MOC）
- AI Agent系统（Skill门禁+触发词+工作流自动化）
- 知识管理方法论（学习技能五步法+原子笔记+知识地图）
- 自动化基建（cron任务+每日热点+周复盘）
- 语音输入校验+多AI协作

## 与现有业务的衔接点

- 4980课程：可以升级为"4980课程+AI框架部署服务"的组合产品
- 数字分身产品：这就是终局"专业人士的第二曲线设计师"的MVP
- 与[[04服务客户/【大连】燕窝/03-定位方案]]的关系：定位→框架部署→长期陪跑，形成完整服务链

## 产品形态确认（2026-06-02 21:19）

**参照模型：Hanako**
- Hanako = 一个独立的OpenClaw Gateway实例，有自己的名字、人格、Skill体系、知识库
- 通过同一个OpenClaw App的WebChat对话，感知上是"独立的AI助手"
- 非独立开发APP，是独立Gateway + 白标聊天界面

**目标形态**：
```
服务器（柯哥管理）
├── Gateway 1 — 小龙（柯哥自己用·新媒体运营）
├── Gateway 2 — Hanako（行业研究）
├── Gateway 3 — 客户A（律师行业AI助手）
├── Gateway 4 — 客户B（烧烤店AI助手）
└── Gateway N — 客户N（XX行业AI助手）

客户端：每个客户打开一个独立品牌的聊天APP → 连到自己的Gateway
```

**关键卡位**：
- 多Gateway架构的隔离性天然适合多客户部署
- 每个Gateway独立配置Skill、知识库、人格——"换行业=换Skill模块"
- "忘不了"机制嵌入Gateway层：品牌名、系统提示、自动报告、模板作者标注

**落地路径（由简到繁）**：
1. 先用OpenClaw原生App + 远程Gateway模式跑通第一个客户
2. 验证需求后再考虑白标封装（改App名/图标/默认连接）
3. 量大了考虑独立APP（fork OpenClaw macOS app定制）

### 1.2 现有接口形态（改造挂载点）

```
LLMProvider 接口（types.ts:58）
  └ chat(request) → LLMChatResult
  └ stream(request) → AsyncIterable<LLMStreamEvent>
  providerId: 'deepseek'|'openai'|'anthropic'   ← 唯一对接面
  profile:    'flash'|'pro'|'reasoning'           ← 档位（映射到 Hermes profile）
```

**核心结论**：`LLMProvider` 接口已是天然 Adapter 抽象。改造不是推翻，而是**把这个接口的实现换掉**——由当前的"直连 LLM 供应商"换成"走 Hermes serve"。

## 二、目标架构（多用户容量导向）

```
用户（APP / 小程序 / 微信）
    │
    ▼
帧言 BFF（无状态 · 可水平扩展）
    │  用户/订阅/运营/商城/队列/限流
    │
    ▼
HermesAdapter ★新增（实现 LLMProvider 接口）
    │  chat / stream / createSession / getState
    ▼
Hermes 节点（有状态 · 长驻）
    hermes serve（JSON-RPC/WebSocket）
    每用户一个 profile（独立记忆/技能/会话隔离）
```

### 2.1 四个架构件（现在就要写对）

1. **HermesAdapter**：实现 `LLMProvider` 接口，内部调 `hermes serve`。业务层零改动。
   - `chat()` → JSON-RPC `chat` 方法
   - `stream()` → WebSocket 流式
   - 新增 `createSession/getState` → 管理每用户 profile + 会话映射
2. **会话映射表**：`userId → { profile, sessions[] }`，进 DB 结构（现 JSON 文件，字段按 5000 用户标准设计）
3. **BFF 队列**：每用户消息串行（LLM 慢防自爆）+ 全局并发上限（可配置）
4. **每用户一个 Hermes profile**：独立记忆/技能/会话隔离

### 2.2 容量阶梯

| 规模 | 部署 | 关键动作 |
|------|------|---------|
| ≤50 活跃 | 本机 M4 | 本机 `hermes serve` + 现有 JSON 存储 |
| ≤500 活跃 | 1 台云 4C8G | +SQLite + BFF 队列（每用户串行、全局并发上限） |
| ≤5000 活跃 | 2-3 节点 | BFF 无状态化 + 用户按 hash 路由节点 + Postgres |
| 10 万级 | 容器集群 | Hermes 节点池 + 自动扩缩（**Adapter 接口不变，只换路由**） |

## 三、技术选型关键决策

### 3.1 对接方式：`hermes serve`（JSON-RPC）✅ 已定

- **为什么不做 CLI 子进程**：每用户消息一个进程 → 启动 1-3s + 上百 MB 内存 → ~50 活跃用户打爆本机（多用户容量考量）
- **为什么直接 JSON-RPC**：一个长驻进程服务所有用户，天然并发；`hermes serve` 是桌面 app 同款协议，headless 常驻

### 3.2 profile 隔离模型

- 每个用户一个 Hermes profile（`~/.hermes/profiles/<userId>/`）
- 独立记忆 / 技能 / 会话 —— 落地柯哥拍板"每个用户有自己的记忆"

### 3.3 技能灰度（柯哥拍板：灰度）

- 先切 **1 个技能（xuanti）** 走 Hermes，其余走旧引擎
- 用 feature flag 控制：`useHermesFor: ['xuanti']`
- 验证 OK 再全量切

## 六、风险与回滚

| 风险 | 等级 | 缓解 |
|------|------|------|
| hermes serve 长驻不稳 | 中 | systemd/launchd 守护 + 心跳重连 |
| profile 隔离破坏多租户 | 高 | 隔离测试：两用户并发不串数据 |
| 技能输出风格漂移 | 中 | 灰度对比 + 校准配置迁移 |
| 老数据格式不兼容 | 中 | 迁移脚本 + 备份 |

**回滚**：全部走 feature flag。任何阶段出问题，关 `useHermesFor` 即回旧引擎，零风险。

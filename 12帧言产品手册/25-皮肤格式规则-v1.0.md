# 帧言 · 皮肤格式规则 v1.0

> 用途：给任何接手皮肤工作的模型/人（Codex、Claude、Hermes）看的**唯一规则源**。
> 柯哥拍板（2026-08-05）：皮肤 = 在本地做好 → 通过超管后台"皮肤管理"上传 → 创作者端/操盘手端用户可选。
> 本文件是"怎么做一套皮肤"的权威说明，动手前必读。

## 一、皮肤是什么

一套皮肤 = **一份 11 色配色 JSON（SkinDef）**。系统根据这 11 个色**自动生成全套 CSS 变量**（纸/墨/玉/朱砂/金 的 50–950 色阶 + 玻璃/阴影/暗纹），前端所有组件都消费这些变量。**做皮肤的人不需要碰任何组件代码。**

## 二、格式（SkinDef）逐字段说明

```jsonc
{
  "id": "songya",          // 唯一标识，英文小写，新皮肤不可与现有重复
  "name": "宋雅",          // 展示名（皮肤卡片上显示）
  "era": "宋",             // 朝代（皮肤卡片上的小字）
  "years": "960–1279",     // 年代区间
  "available": true,       // 是否开放（false 时用户端显示"上新中"锁）
  "note": "汝窑天青与宣纸竹影，夜面为竹夜",  // 一句意境描述（悬停提示）
  "motifs": {              // 【可选】暗纹 SVG（data-url），如青花的缠枝莲
    "light": "url(\"data:image/svg+xml,...\")",
    "dark": "url(\"data:image/svg+xml,...\")"
  },
  "colors": {              // 5 个预览色（皮肤卡片圆点），从 palettes 取主色即可
    "ground": "#F8F1DC", "text": "#292317", "action": "#33735E",
    "alert": "#C22E1D", "accent": "#9B824B"
  },
  "palettes": {            // ★ 核心：11 色 × 昼夜两套
    "light": {
      "ground": "#F8F1DC",        // 页面底色（宣纸）
      "surface": "#FFFBEC",       // 卡片/表面色
      "text": "#292317",          // 主文字（墨）
      "textMid": "#6B5F47",       // 次级文字
      "textSoft": "#A39878",      // 弱文字/占位
      "action": "#33735E",        // 主操作色（玉）
      "actionDeep": "#21453B",    // 主操作深色（hover）
      "onAction": "#FFFBEC",      // 主操作上的文字
      "alert": "#C22E1D",         // 警示色（朱砂）
      "accent": "#9B824B",        // 点缀色（金）
      "accentText": "#6B5A33"     // 点缀上的文字
    },
    "dark": { /* 同样的 11 个字段，夜面配色 */ }
  }
}
```

## 三、硬性规则（违反 = 皮肤不合格）

1. **11 色必须齐**：light/dark 各 11 个字段，一个不能少，全是 6 位 hex（`#RRGGBB`）。
2. **对比度**：`text` 与 `ground`、`onAction` 与 `action` 必须可读（浅底深字 / 深底浅字）。
3. **色调一致性**：一套皮肤的 ground/surface 要是同一纸色系（米/青/灰皆可），action/alert/accent 与主色调和谐，不出现"青花底配亮橙按钮"这种撞色。
4. **id 唯一**：英文小写 + 下划线，不与内置五套（songya/hanqi/tangcai/qinghua/mingtang）及已上传皮肤重复。
5. **dark 不是 light 的简单反色**：夜面要单独调（可参考现有五套的 dark，都是重新设计的深色系，不是 invert）。
6. **motifs 可选**：SVG 必须是 data-url 编码的 `url("data:image/svg+xml,...")` 字符串，stroke 色要与 skin 主色系一致，opacity 控制在 0.05–0.08（淡，不抢内容）。

## 四、上传与分发（超管后台「皮肤管理」）

- 上传入口：超管后台 → 皮肤管理 → 新增皮肤（粘贴/上传 SkinDef JSON）。
- 后端校验：格式校验（字段齐全、hex 合法、id 唯一）→ 通过才入库。
- 下发：客户端登录时拉取皮肤列表，**未自选用户用系统默认皮肤**，用户可在主题设置里自选（自选优先）。
- 更新规则：管理员改默认皮肤/锁按钮 → 保存即下发，新登录用户立即生效；已自选用户不受影响。

## 五、常见坑

- 别改 `themes.ts` 的 `SkinId` 联合类型去硬编码新皮肤——新皮肤走**动态注册**（上传后进 `custom-skins.json`，前端启动时合并），改类型会导致内置皮肤与动态皮肤冲突。
- 别用 Tailwind 默认 `shadow-sm` 等冷灰阴影——帧言审美是**无阴影 + hairline 细线**（`border-ink-800/10`），阴影用 `--fy-shadow-*` 暖调变量。
- 按钮风格：`rounded-[3px]` + `tracking-[0.1em]` + `font-medium`，不用 `rounded-lg + font-semibold + shadow`（那是科技感，不是东方美学）。

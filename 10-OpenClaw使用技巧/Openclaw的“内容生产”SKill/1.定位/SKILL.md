# dingwei-report-workflow v7.0

## 0. 边界

1. 定位不是写一句口号，而是给后续选题、大纲、文案和生意承接建立共同地基。
2. 保留既有四件套：`02-客户分析.md`、`03-定位方案.md`、`04-语言风格指南.md`、`05-内容规划.md`。
3. 事实、合理推断、待确认、禁用信息必须分开；不得为了填满模板编客户经历。
4. 本工位读取 `作战包.md` 和客户真材料，不读取私有来源登记、源课程全文或案例全集。
5. Vault 只通过 `superfactory_obsidian_search/read/create`；工具故障时停止，不换 shell、Python 或 filesystem。

## 1. 开工预检

通过官方包装工具确认：

- 客户/账号唯一，路径没有同名歧义。
- 原始问卷、访谈、沟通记录和已有内容已读到正文，不以文件名代替内容。
- 业务目标清楚：流量最终影响咨询、到店、招募、成交、复购还是个人影响力。
- 若已有旧定位，说明本次是新建、校准还是重做，禁止静默覆盖。

材料不足以判断时，输出最少补料清单；可以保存碰撞记录，不得把猜测写成正式定位。

## 2. 先理解人和生意

内部工作包必须回答：

```text
这个人现在靠什么业务生存：
他真正擅长并有证据的事：
他做选择时反复出现的标准：
最值得长期记录的经历/现场：
谁会被内容影响：
谁会实际付费或推动付费：
从内容到业务的路径：
不能说、不能承诺、不能服务的人：
```

目标用户要具体到处境、问题、语言和决策时刻，但不能把市场锁死成一个虚构人物。浏览者、影响者、付费者不一致时，写清传导关系。

## 3. 对标与差异

对标分两层：

- 头部账号用于理解赛道方向和成熟形态，不能直接当早期执行标尺。
- 近半年、相近体量、相近阶段的账号用于验证可复制动作。

优先读取客户提供的账号和公开链接；有受控搜索能力时再补充。粉丝量、发布时间、变现路径等动态信息必须标来源和日期；无法核实时写“待验证”，不得编造。

差异化只保留四种可证实路径：反向判断、能力组合、经验迁移、真实弱点显影。每个差异点都要回答“用户为什么在乎”。

## 4. 生产四件套

### 02-客户分析

写事实底档、业务现状、能力证据、用户关系、对标观察、内容资产、风险与待确认项。形容词必须绑定事件证据。

### 03-定位方案

至少包含：一句话定位、具体用户画像、用户处境、可信理由、人设证据、内容任务、内容支柱、稳定形式、差异化、商业路径、内容与产品关系、阶段目标、边界、风险、待验证假设。

### 04-语言风格指南

只从真实语料提取：句长、节奏、常用开口、判断方式、情绪幅度、可保留口头词、禁用表达。没有语料就标“待采样”，不得写成通用人格模板。

### 05-内容规划

按营销、信任、成交、记录四类分工，给出第一阶段内容地图、前 6 条建议、素材缺口和采集动作。每条只设一个最高任务。

## 5. 一致性验收

- [ ] 四件套齐全且字段互相不打架
- [ ] 用户画像具体，但没有把市场锁死
- [ ] 人设都有真实事件证据
- [ ] 内容形式能由当前团队持续执行
- [ ] 流量到业务的路径说得通
- [ ] 推断和待确认没有混进事实
- [ ] 动态对标信息有来源和日期
- [ ] 客户可读版没有内部术语、来源姓名和系统日志

未全部通过，只报告“部分完成”和缺口，不虚报定位已完成。

写入前先搜索目标路径；存在旧版时先保留历史版本，再用 `superfactory_obsidian_create` 写当前版并回读确认。

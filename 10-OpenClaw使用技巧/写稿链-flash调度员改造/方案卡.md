# 写稿链「flash 调度员」改造 · 施工方案卡

> 作者：Claude（教练员/架构师）· 2026-07-18 · 柯哥「嗯，开干」授权
> 用途：这是施工蓝图，防会话压缩丢失。断了照这张卡续跑。

## 一、为什么改（病根）

柯哥前台反复撞 `Auto-compaction could not recover this turn`。查证结论：
- `reserveTokensFloor` 现值 35000（报错提示让加到 35000 是**死循环**，早就到头），加了反而缩小有效窗口，是反效果。
- 真病根 = **单轮 prompt 里工具返回值太大**（obsidian_search 甩上百条路径、read 吞大素材正文），落在 `keepRecentTokens` 保留区，压缩碰不掉 → 压完仍超 96k 目标线 → "couldn't trim enough"。
- **同一个根还杀死了周自进化**（weekly-skill-review 旧版 Step 1.4 对 20+ 会话拉 sessions_history×200 撑爆 → 连崩被自动停用）。断片、稿子写飞、不自我进化——是一个系统级病根的三个症状。

## 二、设计：一副骨架，三个工人（柯哥 Gemini 提醒后收敛）

pro 主脑只做**判断+创作**，力气活全外包给隔离工人，工人只回结论/料单。柯哥系统里**已有两个工人在跑**，本次补第三个：

| 工人 | 外包什么 | 交回 pro | 状态 |
|---|---|---|---|
| **flash 读料** | 检索/通读大素材/读三件套（腿活） | 带**原文指针**的料单 + Gemini/舒老师轻量包 | ❌ 本次新建 |
| **Gemini 整流器** | 审美打磨 + 蒸馏成可复用规则 | 差异拆解 + ≤1200字轻量反哺包 | ✅ 已有（§8 自带 context 保护） |
| **盲打分 Channel B** | 独立评分防自评虚高 | 5 项分数+理由 | ✅ 已有 |
| **pro 主脑** | 六闸/搭粗坯/写稿七检/人设雷达/终审 | —（手感全留，一字不动） | 不变 |

## 三、flash 读料工人 spec（复刻 yuyin 已跑通模板）

- **参数写死**（同 yuyin）：`model: deepseek/deepseek-v4-flash`、`context: isolated`、`cleanup: delete`。叶子层无 spawn 权限防递归。
- **分身干**：fanwen §1 dagang 检索 + §2.2 读客户三件套 + §2 通读大素材原话。
- **分身回传一份「读料料单」**（不回全文，防污染 pro）：
  - 工作包沉淀：画像 / 气口 / 事实清单 / 禁区（可归纳）
  - **四类载重内容必须逐字 verbatim（🔴 禁归纳/润色/补全）**：
    1. 人设核心特质那一行（§3.4 人设漂移雷达的对照锚）
    2. 03-定位方案 / 04-语言风格指南里的红线原文
    3. 候选进稿的素材原话（含停顿、别扭、犹豫、情绪锚）
    4. **每一个数字及其出处**（年龄/年份/次数/天数都算）
  - 每条料带**五类出处标签**（原始素材/客户档案/dagang/模型桥接/待本人确认）+ **原文段落锚点**（pro 起疑可回读小段核对）
  - Gemini 轻量反哺包 + 舒老师轻量反哺包（命中当前客户/IP 才下钻最多 3 个差异拆解；**名称机械匹配，非审美判断**）
- **pro 从「放行卡判断」接手**：放行 PASS/BLOCKED、哪些是 IP 生命力、高风险主张删降级——**全是判断，留 pro**。
- **Fail-safe**（同 yuyin）：spawn 不可用 / 分身失败 / 回传空 → 退回 pro 本会话分批读，不等柯哥催。

## 四、§2.2「两小时前必须重读」铁律怎么改（关键接缝）

这条初衷 = **不让 pro 被压缩换血的记忆充当人设锚/原话的真理来源**（袁姐 42/43 稿根因）。flash 方案满足初衷，改写为：
> 本轮由 flash **现读**回传料单（带时间戳，不吃上一轮缓存），pro **只认本轮料单、不许回退自己的 context 记忆**；四类载重内容 verbatim。

保留括号内袁姐事故根因说明。**反模式（靠压缩记忆当真理）照旧禁止**，只是把 reader 从 pro 换成 flash。
